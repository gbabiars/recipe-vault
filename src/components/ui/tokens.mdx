# Token usage

Use the design-system tokens and component props to keep UI consistent across
the app and MCP views. `src/app/globals.css` owns token names, values, and theme
definitions. This guide describes how to choose them; it does not duplicate the
token catalog.

## Prefer shared values

1. Use a design-system component for a common UI job.
2. Use its layout or appearance props when they express the need.
3. Use semantic tokens in a CSS Module for local styling that remains.

For example, use `Stack gap="200"` for standard vertical spacing. If a local
value has no suitable prop or token, use a component-specific value. Add a
shared token only when the value represents a reusable design role. Do not
start a migration just because existing CSS contains literal values.

Choose semantic color tokens by meaning and state so light and dark themes keep
the same intent. Use the existing focus tokens for focus treatment and pair
color-coded states with text or another visible cue. Component family guides
show the relevant choices for their controls and surfaces.

## Responsive layout

Use the shared responsive definitions in
[`src/components/ui/viewport.css`](./viewport.css) from CSS Modules. In client
components, `useBreakpoint` uses the same breakpoint names; see its component
docs for the current API and behavior. `GridItem` responsive props use
container widths, so consult its family guide when choosing between container
and viewport behavior.

See the [UI composition standard](../../../docs/standards/ui/composition.md) for the full component-first styling
rule and the [component index](./index.mdx) for family documentation.
